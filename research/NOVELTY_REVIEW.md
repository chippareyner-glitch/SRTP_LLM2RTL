## 结论先行

1. **"提问代替投票"这个方法本身不是我们最强的创新点。** RTL 领域有 SpecLens、VClare，软件领域有 TiCoder、ClarifyGPT、SpecFix，各自覆盖了它的主要部分。
2. **最值得作为主线的是两个"发现型"贡献：**
   - **A1 选择空间受规格约束**：对强模型而言，"投票失败但池里有正确答案"的剩余空间，主要被规格缺陷和测试薄弱占据，而不是被模型能力占据。
   - **A2 无参考的规格缺陷探测**：精度经人工裁定测量，并附有实际发现的缺陷清单。
3. **两处旧说法需要修正**（已在各报告中加注）：
   - "5 处首次发现的缺陷"偏高。SpecLens 已列出 RTLLM `fixed_point_substractor`，也报告过 `alu` 的另一个问题。

## 2. IDS 的等样本数对照（新做）

原报告比较的是"基础 5 个样本"和"基础 5 个 + IDS 最多 4 个"，样本数不同。这里固定池大小为 5：

- 把基础样本随机换成 IDS 设计，对所有子集取期望；
- 只统计基础池恰有 5 个样本的题。

| 基准 | 题数 | 基础 n=5 解出 | IDS 换入、仍为 n=5 | 原报告的不等量比较 |
|---|---|---|---|---|
| VerilogEval | 156 | 142.0 | **141.8** | 145 |
| RTLLM | 40 | 35.0 | **37.0** | 37 |
| CVDP | 67 | 49.0 | **49.4** | 50 |

单个样本的质量（只统计有 ≥4 个 IDS 设计的题）：

| 基准 | 基础 pass@1 | IDS pass@1 |
|---|---|---|
| VerilogEval | 70.6% | 49.6% |
| RTLLM | 80.8% | 74.0% |
| CVDP | 56.5% | 46.6% |

**解读：**

- **VerilogEval、CVDP：** 一个 IDS 设计带来的覆盖，约等于一个普通样本；但单个 IDS 设计更容易错。强制模型采用某种解读，常常就是采用了错误的解读。
- **RTLLM：** 等量下多解出 2 题。这是真实收益，但样本太少，不足以作为主张。
- **CVDP 原报告的数字有混杂。**
  - pass@any 65.4 → 70.5（+4 题）中：
    - `unpacker_one_hot`、`vga_controller` 两题的基础池因 API 欠费是**零样本**；
    - `apb_dsp_unit` 只有 3 个基础样本。
  - 多数投票 60.2 → 64.5（约 +3.4 题）中，也有 2 题来自这两个零样本题。
- **因此：**
  - "IDS 是更好的生成策略"不能作为创新点；
  - "IDS + AskRTL 不需要人即可达到 90.1%"（VerilogEval）同样是不等量比较，需要用基础池 n=9 作对照才能成立，这需要付费生成。

## 3. 创新点重新分级

### A. 可以作为主卖点

**A1 选择空间受规格约束（诊断性发现）**
- **证据：**
  - 强模型自评时，VerilogEval 的 7 道"有正确候选但投票失败"题中，6 道是规格缺陷、规格含糊或标签问题；
  - CVDP 上选择最多只能再提升约 5 个点，22 题没有任何正确候选；
  - CVDP 上 19–25 个问题的所有选项都能通过官方测试，也就是说，评测根本看不到选择的对错。
- **新颖性：** 中高。SpecLens、VRank、VFocus、EAHC、VClare 都在做"选择"，但没有人量化过选择的剩余空间由什么构成。
- **弱点：**
  - 只用了一个模型家族；
  - 关键子集很小（7 题）；
  - "弱生成器 + 强评审 = +4.4 点"的对照有混杂：旧候选池每题约 9.5 个样本、来自 6 种配置；新池是单一配置的 5 个样本。

**A2 无参考的规格缺陷探测，精度可度量**
- **证据：**
  - 人工裁定 18 个标记，78–83% 指向真实规格问题；
  - 找到 3 道新缺陷题、1 处已知题中的新问题；
  - CVDP 中 4 道题的接口名与测试平台不一致；
  - CVDP 中 15/48 道题的测试约束偏弱（行为不同的设计都能通过）。
- **新颖性：** 中。软件领域有 SpecFix 的语义熵思路。RTL 领域：
  - SpecLens 是人工审计；
  - VClare 的缺陷全是注入的；
  - RTL-BenchMT 是 agent 辅助审计；
  - 都没有给出"自动标记 → 人工裁定"的精度。
- **弱点：** 召回有盲区。所有样本以同一种方式误读规格时，不会产生分歧，也就不会被标记。

### B. 方法层面的增量（作为工具描述，不单独宣称）

**B1 提问形式**
- **具体做法：**
  - 用 delta debugging 最小化时序轨迹；
  - 按期望信息增益选择问题；
  - 允许回答 ANY / NONE / UNCLEAR；
  - 按采样配置计票作为先验。
- **相对已有工作的差别：**
  - 与 TiCoder、ClarifyGPT 相比，多了"时序轨迹最小化"；
  - 与 SpecLens、VClare 相比，多了 ANY 选项和信息增益提问。
- **ANY 选项的作用：** 它把"规格不约束"变成可观测的信号，正是 A2 的输入。
- **成本：** 约 14K token/题。比 SpecLens 少一个数量级，但模型和流程都不同，不能直接对比。

**B2 人机混合的提问量**
- VerilogEval 全基准只问用户 6 个问题，准确率 +2.6 点。
- VClare 没有报告这一数字。

### C. 支撑性结果与否定结果

否定结果：
- **不背诵教科书设计：** 0/12 回退。直接回应了 SpecLens 文中"基线常回到原基准实现"的旁注。
- **约定类错误只占 8%。**
- **最短轨迹不更准，只是便宜 39%。**
- **参数扫描没有用。**
- **IDS 不是好的缺陷探测器。**
- **新增：** IDS 在等样本数下没有覆盖优势。

## 4. 建议的主线叙事

> **"当模型对 RTL 规格意见不一时，错的通常是规格"**：一项测量与审计研究。AskRTL 是测量工具，而不是卖点。

**论文结构：**
1. 选择空间分解：pass@1 → 多数投票 → 评审选择 → pass@any → 规格可解。在 3 个基准上按原因拆解差距（A1）。
2. 分歧加评审作为规格缺陷探测器：给出精度、召回盲区和缺陷清单（A2）。
3. 对实践的启示：
   - 对用户，在出现分歧时提一个具体问题，而不是静默投票（B2）；
   - 对评测，报告分数时单列规格缺陷题和测试薄弱题。
4. 否定结果作为设计空间的约束（C）。

## 6. 第二轮：在已有数据中新挖到的候选创新点（2026-10-11）

### N1 规格–测试双向对齐审计

**思路。** 候选之间的每个分歧问题，都是一个天然的探针。它可以同时问两件事：

- **测试能否区分**：用官方测试判每个选项背后的簇是否通过；
- **规格是否规定**：看评审的回答。答具体选项，表示规格有规定；答 ANY 或 UNCLEAR，表示规格没规定。

由此得到四格：

| | 规格有规定 | 规格没规定 |
|---|---|---|
| **测试能区分** | 对齐 | **偏严（OVER）**：测试拒绝了规格允许的实现，有误判失败的风险 |
| **测试分不出** | **偏松（UNDER）**：测试接受了规格不允许的实现，有误判通过的风险 | 合理宽松 |

**结果**（[askrtl/alignment.py](askrtl/alignment.py)，零 API 花费）。下表单位是"问题次数（涉及题数）"：

| 候选池 | 对齐 | 偏严 | 偏松 | 合理宽松 |
|---|---|---|---|---|
| VerilogEval，基础池 | 10 | 4（2 题） | 1（1 题） | 0 |
| VerilogEval + IDS | 62 | 7（4 题） | 4（3 题） | 0 |
| RTLLM，基础池 | 3 | 0 | 4（4 题） | 2 |
| RTLLM + IDS | 17 | 0 | 8（6 题） | 2 |
| CVDP，基础池 | 14 | 3（1 题） | **15（10 题）** | 4 |
| CVDP + IDS | 26 | 5（3 题） | **21（10 题）** | 4 |

**原始统计呈现的模式**（⚠ 第 7 节人工裁定后**不成立**，保留在此作为记录）：

- **VerilogEval 偏严。** 它的测试在随机激励上与参考设计逐拍比较，相当于要求等价。所以规格没写的地方也被强制，例如 Prob070 中"不会出现的输入"、Prob153 的复位值。
- **RTLLM 和 CVDP 偏松。** 它们是定向测试，规格写明的行为也常常没有检查。

另一个角度：官方通过的样本中，被评审高置信（≥0.9）否定的比例。

| 基准 | 比例 | 解读 |
|---|---|---|
| VerilogEval | 1.7% | 可看作噪声底，其中也包括已知规格缺陷 |
| RTLLM | 7.7% | 明显高于噪声底 |
| CVDP | 10.9% | 明显高于噪声底 |

**人工核对**：抽查 6 个 CVDP 偏松问题。

| 判定 | 数量 | 题目与说明 |
|---|---|---|
| 真实的测试漏洞 | 3 | `thermostat`：规格明写 `i_fan_on=1` 时风扇开，1 个样本违反却通过测试。`complex_multiplier`：有符号或无符号未写明，但"复数实部"隐含有符号。`axi_register`：复位期间 `wready` 随输入拉高 |
| 惯例上属于"不关心" | 2 | `cascaded_adder`、`decode_firstbit`：都是 valid 为低时数据输出的取值，评审却判为必须 |
| 评审过度确定 | 1 | `bcd_counter`：规格没写同步还是异步复位 |

所以偏松这一格的精度约为一半。另外，评审**几乎从不对"valid 为低时的数据"回答 ANY**。这是评审自身偏严的系统性偏差，可以用一条规则修正：对受 valid 门控的输出视为不关心。

**与先行工作的区别：**

| 工作 | 做法 | 局限 |
|---|---|---|
| GateTruth（2608.12635） | 对参考设计做变异测试 | 依赖参考设计 |
| RealBench（2507.16200） | 用 JasperGold 做形式验证：RTLLM v2 中 44% 通过测试的设计未通过形式验证 | 依赖参考设计；会把规格没规定的差异也判为错 |
| NotSoTiny（2512.20823） | 与参考设计做 k=30 的有界等价检查 | 同上 |
| RTL-BenchMT | agent 辅助审计 | — |
| SWE-bench Verified（软件） | 人工标注"问题描述不足"和"测试过严" | 人工；不针对 RTL |

我们的做法：
- 不需要参考设计，所以可用于参考设计不公开的 CVDP；
- 探针是模型自然产生的不同实现，而不是人工变异；
- **区分"规格是否规定"**。

由此可以提出一个反直觉的论点：**更严的评测不一定更好。** 形式等价评测会把偏严和合理宽松两格中规格允许的实现都判为错误，也就是把 VerilogEval 式的偏严推广到所有基准。

**评估：** 新颖性中高；证据目前中等，偏松一格的精度约 50%，还需要更多人工裁定。

### N2 LLM 生成 RTL 的错误具有"小范围"性质

下表统计"正确候选 vs 错误候选"的最短区分轨迹长度，单位是复位后的周期数：

| 候选池 | 对数 | 中位数 | ≤1 周期 | ≤3 周期 | ≤8 周期 |
|---|---|---|---|---|---|
| VerilogEval，旧候选池 | 102 | 1 | 51% | 77% | 90% |
| VerilogEval + IDS | 120 | 1 | 63% | 87% | 92% |
| RTLLM + IDS | 49 | 1 | 53% | 80% | 94% |
| CVDP + IDS | 120 | 2 | 42% | 76% | 94% |

**意义：**
1. 深度约 8–10 的有界等价检查（BMC）就能区分绝大多数候选。可以用它代替随机仿真，得到"在界内完备"的聚类。
2. 交给人回答的问题只有 1–3 行，所以人机交互是可行的。

**注意：** 这些轨迹由随机仿真发现后再最小化，会偏向浅层差异。需要用有界模型检查独立验证：要装 SymbiYosys，不花 API。

**评估：** 新颖性中等。软件里有 Alloy 的 small scope hypothesis，但没见过针对 LLM 生成 RTL 的度量。

### 更新后的主线建议

> **"分歧是探针"：用 LLM 候选之间的分歧，同时审计规格（A2）、测试（N1）和选择方法的上限（A1）。**

这比任何单项都新：
- 现有工作要么只审计规格（SpecLens、RTL-BenchMT），要么只审计测试（GateTruth、RealBench）；
- 而且都依赖参考设计或人工。

- 裁定数据：[askrtl/adjudication_n1.json](askrtl/adjudication_n1.json)
- 补充测试：[askrtl/supp_tests.py](askrtl/supp_tests.py)，输出在 `askrtl/supp_tests/`
- 汇总：[askrtl/alignment.py](askrtl/alignment.py) 第 4 部分

### 7.1 裁定结果

偏严、偏松两格共 72 个问题次数，去重后为 50 个独立问题，分布在 34 道题上。每个问题都按评审当时看到的提示逐个阅读：规格、最短轨迹、选项、各簇的官方通过情况，以及评审的推理。

**偏严（11 个）：只有 1 个属实。**

| 判定 | 数量 | 题目 |
|---|---|---|
| 属实 | 1 | VerilogEval Prob153：PHT 复位值规格没写，测试要求参考设计的取值 |
| 评审答错，规格其实有规定 | 3 | Prob154：评审忽略了第三个选项。Prob091、Prob150：规格要求"by inspection"推导，评审却说非法 one-hot 输入不约束；评审在 Prob079 上的做法与此相反。后两者有争议 |
| 部分 ANY | 2 | 评审的 ANY 只覆盖部分选项，测试拒绝的正好是被排除的那个，实际上是对齐的 |
| 归因错误 | 4 | 失败的簇是因为别的问题失败。例如 16QAM 的官方测试只用合法星座点 |
| 工具伪迹 | 1 | GFCM 时钟选择器被当成组合逻辑仿真 |

**偏松（39 个）：**

| 判定 | VerilogEval | RTLLM | CVDP | 合计 |
|---|---|---|---|---|
| **真实测试漏洞**（违反规格明文的设计通过了官方测试） | 3 | 1 | 5 | **9** |
| valid、done、start 类信号为低时的数据输出（按惯例不关心） | — | 3 | 5 | 8 |
| 协议不关心（复位期间输入 valid 为高） | — | — | 1 | 1 |
| 规格没写，评审过度确定 | — | 1 | 7 | 8 |
| 规格有歧义或自相矛盾 | — | — | 7 | 7 |
| 规格缺陷 | — | 3 | 1 | 4 |
| 工具伪迹（输入变化与时钟下降沿重合） | 1 | 1 | — | 2 |

**结论：**

1. **自动矩阵的精度很低。** 偏松一格为 9/39 = 23%，偏严一格为 1/11。上一轮"VerilogEval 偏严、RTLLM/CVDP 偏松"的模式不成立。按题计算的真实测试漏洞：VerilogEval 2/156，RTLLM 1/42，CVDP 5/73。
2. **valid 门控规则很准，但不够。** 规则写法：选项只在数据输出上不同，且所有 valid、done、ready、start 类输出都为低时，视为不关心。它与人工标签完全一致（TP 8 / FP 0 / FN 0）。加上规则后，偏松精度也只升到 9/31 = 29%。
3. **主要噪声来源是评审过度确定。**
   - 在"所有选项都能通过测试"的 65 个问题次数中，评审只有 12 次答 ANY 或 UNCLEAR。
   - 它给出具体答案的独立问题里，15 个其实是规格没写或有歧义。
   - 评审的置信度区分不出这两类：错误的判断也多在 0.95 以上。
   - 这也限制了 A2 的召回率，以及人机混合中"不确定就转交用户"的路由。
4. **但这些标记仍是很好的"有问题"信号。** 9 个测试漏洞、4 个规格缺陷和 15 个规格歧义加起来，共 28 个指向真实的基准问题。用 valid 门控规则过滤后，比例为 **28/31 = 90%**。只是评审分不清问题出在规格还是测试，这一步需要人来判断。

### 7.2 补充测试

把 9 个真实漏洞各转成一条可执行测试：施加问题的最短激励，在分歧时刻检查选项间有差异的输出必须等于规格要求的值，不得为 X。然后在每道题 IDS 池的全部设计（基础样本 + 解读设计）上实际仿真。

| 题目 | 来源 | 参考设计 | 官方通过但违反补充测试的设计 |
|---|---|---|---|
| Prob079_fsm3onehot | VerilogEval | 通过 | 1（IDS） |
| Prob143_fsm_onehot × 2 | VerilogEval | 通过 | 各 1（IDS） |
| JC_counter | RTLLM | 通过 | 1（IDS） |
| axi_register_0001 | CVDP | 无 | 1（IDS） |
| complex_multiplier_0001 | CVDP | 无 | 2（1 个基础样本 + 1 个 **held-out** IDS 设计） |
| dbi_0001 | CVDP | 无 | 1（IDS，复位期间输出 X） |
| filo_0005 | CVDP | 无 | 1（基础样本）；4 个 held-out IDS 设计都通过 |
| thermostat_0001 | CVDP | 无 | 1（基础样本）；3 个 held-out IDS 设计都通过 |

- **一致性：** 有参考设计的 4 条测试，参考设计全部通过。
- **held-out 检验：** 由基础池问题生成的 3 条测试，在 11 个未参与生成的 IDS 设计上运行：
  - 抓到 1 个违规设计：complex_multiplier 的 `i01.sv`，它把输入零扩展，做的是无符号乘法；
  - 其余 10 个都通过。
- **对通过率的影响很小：**
  - CVDP 基础池单样本通过率 59.9% → 59.1%（3 个样本），pass@any 不变；
  - VerilogEval 和 RTLLM 的基础池不变，被抓到的都是 IDS 设计。
- **一个排错记录：** 第一次运行时，axi_register 的期望值用错了字母：裁定时看的是打乱后的显示字母，期望值必须用规范字母。脚本现在会核对期望值与评审的原始答案。

### 7.3 对创新点的影响

| 项 | 修正后 |
|---|---|
| N1 规格–测试对齐审计 | **降级。** 思路成立，但自动工具噪声大。可以写成"分歧探针 + 一条规则 + 人工裁定"的半自动审计：90% 的标记指向真实问题，并附 9 个带反例的测试漏洞。但它对分数影响小，也没有基准间的鲜明对比，不宜作为主卖点 |
| A2 规格缺陷探测 | **得到加强。** 在测试分辨不出的分歧里，扣除 valid 门控后约 90% 是规格或测试问题，与 A2 的 78–83% 精度互相印证 |
| 新的负面发现 | **LLM 评审几乎不承认"规格没写"。** 这是自动审计和人机路由的共同瓶颈 |
| 由此引出的方法点子 | 把问法从"哪个是对的"改成"规格是否**允许**这个选项"（逐项判断是否允许），专门针对过度确定。需要付费验证：约 50 个问题，约 0.3M token |
