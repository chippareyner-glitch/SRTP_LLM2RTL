[ORIGINAL SPECIFICATION]

I would like you to implement a module named TopModule with the following
interface. All input and output ports are one bit unless otherwise
specified.

 - input  clk
 - input  reset
 - input  in
 - output done

In many (older) serial communications protocols, each data byte is sent
along with a start bit and a stop bit, to help the receiver delimit bytes
from the stream of bits. One common scheme is to use one start bit (0), 8
data bits, and 1 stop bit (1). The line is also at logic 1 when nothing
is being transmitted (idle).

Implement a finite state machine that will identify when bytes have been
correctly received when given a stream of bits. It needs to identify the
start bit, wait for all 8 data bits, then verify that the stop bit was
correct. If the stop bit does not appear when expected, the FSM must wait
until it finds a stop bit before attempting to receive the next byte.
Include a active-high synchronous reset. Note that the serial protocol
sends the least significant bit first.

Assume all sequential logic is triggered on the positive edge of the
clock.

## 1. Specification Summary

- **Start bit**: logic 0 after idle state (logic 1)

## 4. Edge Cases & Boundary Conditions

**Critical Edge Cases:**
- **False start**: Line glitches from 1→0→1 during IDLE
- **Missing stop bit**: Start bit followed by 8 data bits but stop bit never arrives
- **Early start**: New start bit appears before expected stop bit in error case
- **Reset during reception**: Reset asserted mid-byte reception
- **Continuous transmission**: Back-to-back bytes without idle time
- **All-zero data**: Data bits = 0x00 could be mistaken for extended start condition

## 5. Functional Correctness Prediction

**Potential Failure Points:**
- **Stop bit validation**: FSM may incorrectly accept a data bit as stop bit if timing not properly controlled
- **Re-synchronization**: Error recovery may cause missed valid start bits during recovery process
- **Meta-stability**: No input synchronization specified for asynchronous serial input
- **Consecutive bytes**: May fail if FSM doesn't return to IDLE quickly enough after stop bit

## 6. Actionable Guidance for RTL Generation

**Design Requirements:**
```systemverilog
module TopModule (
    input  logic clk,
    input  logic reset,    // Active-high synchronous reset
    input  logic in,       // Serial input bitstream
    output logic done,     // Pulse for 1 cycle when byte successfully received
    output logic [7:0] data_out,  // ADD: Received data bits
    output logic error     // ADD: Frame error (stop bit missing)
);
```

**FSM States:**
1. **IDLE**: Wait for start bit (in=0), monitor for glitches (debounce)
2. **RECEIVE_DATA**: Shift in 8 bits LSB-first, counter-controlled
3. **CHECK_STOP**: Verify stop bit (in=1)
4. **ERROR_RECOVERY**: Wait for next stop bit if missing

**Implementation Rules:**
- Sample `in` on rising clock edge only
- **`done`**: 1-cycle pulse after valid stop bit detection
- **`error`**: Assert if in≠1 during CHECK_STOP state, remain asserted until stop bit found
- **Glitch protection**: Require 2+ consecutive 0's to validate start bit
- **Reset**: Return to IDLE state, clear all counters and data registers

**Timing Specification:**
- 1 clock cycle per bit period (simplified assumption)
- Minimum 1 idle cycle between bytes (stop bit to next start bit)

**Verification Requirements:**
- Test all 256 data patterns with valid stop bits
- Test missing stop bit scenarios
- Test reset during each reception phase
- Test maximum consecutive byte rate
- Test false start bit recovery
